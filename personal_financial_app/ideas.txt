Flow
1. Manual entry → POST records/ creates FinancialRecord directly
2. PDF upload → POST statements/ → process_statement() extracts transactions → stored as ExtractedTransaction (status: review_pending) → user confirms via confirm action → creates FinancialRecord
3. All analytics/export views query FinancialRecord (optionally filtered by start_date/end_date/type/category) and compute aggregations on the fly
4. Snapshots are pre-computed monthly rollups stored in FinancialSnapshot, generated manually via POST snapshots/generate/
5. AI analysis sends current financial context to local Ollama; if offline, falls back to a hardcoded rule engine that assesses savings rate, top categories, and goal progress
